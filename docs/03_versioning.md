# 03 版の管理

## 版

- 形式は `YYMMDD-n`（例 `261016-1`。同じ日の 2 回目は `261016-2`）
- 版は**書き出したときに付く**。PSD を保存しただけでは付かない
- 前の版から何も変わっていなければ、版を増やさずに終わる

## PSD に記録するもの（XMP）

| 項目 | 内容 |
| --- | --- |
| `uiexp:ScreenId` | 画面 ID（例 `Home`）。初回だけ指定し、以後は PSD の値を使う |
| `uiexp:BaseVersion` | この PSD が元にしている版（＝最後に書き出した版） |

名前空間は仮に `http://example.com/ns/uiexport/1.0/`（社内で決めたものに置き換える）。
PSD を複製・別名保存しても XMP は付いていくので、続きとして扱える。

## 書き出すときの判定

| PSD の「元にした版」 | 扱い |
| --- | --- |
| フォルダの最新の版と同じ | 書き出す（新しい版になる） |
| フォルダの最新より古い | 止めて知らせる（古いバックアップや別案の可能性）。上書きしてよければ強制する |
| 記録が無い（2 回目以降） | 止めて知らせる（新しく作り直した PSD など） |

別案として残したい場合は、別の画面 ID で書き出す。

## Python 版で確かめたこと

- 同じ PSD を 2 回書き出す → 変更なし、版は増えない
- 記録の無い PSD → 止まる
- 複製して名前を変えて書き出す → 次の版になり、差分に「追加 1 / 削除 1」（名前の変更は削除＋追加に見える）
- 古い PSD から書き出す → 止まる

名前の変更を「変更」として扱うには、PSD のレイヤー ID で照合する必要がある（未実装）。

## Unity での照合（予定）

ID（Unity 上の名前のパス）で、前回取り込んだ記録・新しい書き出し・今の Unity の状態の 3 つを比べる。

| 持ち分 | 項目 |
| --- | --- |
| デザイン | 位置・大きさ・画像・色・アニメーション |
| エンジニア | スクリプト・イベント・エンジニアが追加した部品 |

構造（親子関係、部品の有無）をどちらの持ち分にするかは、取り込みツールを作るときに詰める。
