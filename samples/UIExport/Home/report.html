PSD → UNITY 構造

UI の Unity 構造レポート

PSD のレイヤー名に付けた印から、Unity（uGUI）の階層・位置とサイズ・LayoutGroup・Prefab・テキスト枠を組み立てた結果です。印の抜けや食い違いは「提案」として一覧にしています。AE と Unity は使わず、PSD だけから作っています。

印の早見表（名前の末尾に付ける。Unity の名前からは外す）

_Grpゲームオブジェクトとして残す（大きな親も、ボタンやバッジなどの小さな部品も）
_Listレイアウトグループ。直下の子は印が無くても並びの項目になる
_PrefabPrefab にする（_Grp / _List に重ねる）
_Img中身ごと 1 枚の画像にする（文字やレイヤースタイルも焼き込む）
_Base親自身の画像にする（バッジの赤丸、ボタンの背景など）
area_レイヤーの先頭に付ける。文字の枠、またはグループの範囲
space_レイヤーの先頭に付ける。並びの間隔、内側の余白、画面端からの距離。area_ と同じく表示・非表示に関係なく構造情報としてだけ使う

PSD に重ねた構造

枠をクリックすると、下の階層ツリーと詳細に移ります。Prefab は実線が _Prefab で指定したもの、破線が同じ構造の繰り返しから見つけた候補です。間隔の帯は、オレンジが揃っている間隔、赤が他とずれている間隔です。

提案と指摘

エラーは直さないと Unity で問題になるもの、注意は印と中身が食い違っているもの、提案は印の付け忘れの可能性です。提案は採用するかどうかをデザイナーとエンジニアで決めます。

並び（_List）

グループ向き項目ピッチ / spacing間隔の根拠項目の大きさ並び順確からしさ

Prefab

太い枠は _Prefab で指定したもの、細い枠は印が無いが同じ構造が繰り返されている候補です。

補足

組み立ての前提
  • キャンバスは PSD と同じ 1920×1080。位置は親の中心を原点、上向きを正とする Unity の anchoredPosition で示し、pivot は中央。space_ で画面端（親の端）からの距離が指定された部品だけ、その端に anchor と pivot を合わせ、距離をオフセットにする。
  • space_ は置いた場所で意味を判定する。_List の項目の間は間隔、容器の端と部品の間は、_List なら内側の余白、それ以外なら端からの距離。片側だけ接している場合は、指定の値と実際の間隔の食い違いとして知らせる。
  • ゲームオブジェクトの大きさは、area_ があればそれ、無ければ _Base の画像、それも無ければ中身の範囲。
  • 印の無いグループは、画像だけなら 1 枚にまとめ、文字や印付きを含むならグループを外して中身を一番近い印付きの親に入れる。
  • 並びの向き・間隔・順番は位置から判定（許容差 3px）。LayoutGroup が上書きするのは直下の子の位置とサイズだけなので、並び全体を動かすことや、子の拡大縮小・回転・不透明度を動かすことは問題ない。子の位置を個別に動かす場合だけ、その子を「枠＋見た目」の 2 段にする。
  • コンポーネントの「?」は候補。Button は Btn_ / Button_ で始まるゲームオブジェクトに付けている。文字は TextMeshPro を想定し、数字だけの文字は実行時に変わる候補として印を付けた。
