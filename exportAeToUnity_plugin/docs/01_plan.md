# 01 After Effects パネルの計画（未着手）

アニメーションが要る画面のために、After Effects（AE）で動きを付ける作業を支えるパネル。
**1 つのパネルで「AE ファイルの構築」と「解析・検査・修正・動きのデータの書き出し」を行う。**

```
UIExport/<画面ID>/（layout.json・images）─[構築]→ AE ファイル ─（デザイナーが動きを付ける）
   ─[検査・修正]→ [動きのデータの書き出し] → Unity 取り込みツールが ID で当てる
```

## 構築（layout.json から AE ファイルを作る）

1. 書き出しフォルダ（`UIExport/<画面ID>/`）を選ぶ
2. `images/` の画像を読み込む（同じ絵 `shared: true` は 1 つのフッテージを使い回す）
3. 画面サイズ（layout.json の `canvas`）のコンポジションを作る
4. Unity と同じ親子関係のレイヤーを作る（`tree` をたどる）
   - **アンカーポイントを Unity の pivot に合わせる**（AE で回転・拡大したときに、Unity と同じ点を中心に動く）
   - **レイヤー名は Unity の ID（`unity.name`）にし、ID（親からのパス）をレイヤーのコメントにも記録する**
     （レイヤー名を変えられても、コメントから元の部品が分かる）
   - 文字（`role: text`）は AE のテキストレイヤーにするか、画像にするかを決める（未決定）
5. **どの版の layout.json から作ったかをプロジェクトに記録する**（`version`。動きのデータにも書く）

## 検査（付けた動きが Unity で再現できるか）

| 検査 | 内容 |
| --- | --- |
| ID | レイヤーの ID が layout.json と合っているか（消えた・増えた・名前が変わったレイヤー） |
| 動きの種類 | Unity で再現できる動きか（位置・拡大・回転・不透明度など）。エフェクトやマスクの動きは対象外として知らせる |
| イージング | AE のイージングが Unity 側の形式に変換できるか |
| 焼き付け | エクスプレッションやタイムリマップを使っているか。使っていればフレームごとの値に焼き付ける必要がある |
| 構造 | 親子関係や部品の有無が layout.json と違わないか |

- **構造は AE で変えない。** 変えたいときは PSD に戻して直し、書き出し直す（直す場所を 1 つにする決まり。直下の `docs/06_decisions.md`）
- 名前で直せるもの（ID の綴りなど）は、Photoshop プラグインと同じく修正ボタンを付ける

## 動きのデータの書き出し

形は未決定（直下の `docs/05_motion_format.md`）。ID・元にした layout.json の版・キーフレーム・イージングを持つ。

## 後で作るもの

- layout.json が新しい版になったとき、**付けた動きを残したまま、位置や画像だけ更新する**機能（ID で照合する）

## 未決定のこと

| 項目 | 候補・論点 |
| --- | --- |
| グループの作り方 | ヌルレイヤーの親子付け / プリコンポーズ（入れ子のコンポジション）。動きの付けやすさと Unity との対応で比べる |
| ファイルの単位 | 1 ファイル 1 画面か、複数の画面を 1 ファイルにまとめるか |
| パネルの技術 | AE の UXP は現在ベータ。**作る時点で正式版になっていれば UXP**、そうでなければ ExtendScript（CEP パネル）などから選ぶ |
| 文字 | テキストレイヤーにする / 画像にする |

## 作り方の方針

- 解析や照合の中身（layout.json の読み取り、ID の照合、動きの検査、動きのデータの組み立て）は、
  **アプリに依存しない部分に分けて作る**（Photoshop プラグインの `core/` と同じ考え方。Node でテストできるようにする）
- AE とのやり取り（レイヤーを作る、キーフレームを読む）だけを、AE に依存する部分に置く
