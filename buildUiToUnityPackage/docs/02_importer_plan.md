# 02 取り込みの計画（残作業）

エディタ拡張（C#）。`UIExport/<画面ID>/` の `layout.json` と `images/` を読み、画面の GameObject を組み立てる。
エンジニアが手で並べる作業を無くすのが目的。layout.json は人が読むものではなく、このツールが読むもの。

読む項目と意味は、直下の `docs/04_layout_format.md`（layout.json の形の正）を見る。

## 段階 1 で決めたこと（2026-10-17）

| 項目 | 決めたこと |
| --- | --- |
| 置き先 | シーンの Canvas（Canvas を置かないとレイアウトした意味が無いため）。**今のシーンに追加**するか、**保存先を選んで新しいシーンを作る**か |
| 同じ名前の画面がシーンにあるとき | 置き換える / 並べて追加 / やめる を選ぶ（再取り込みでの更新は段階 2） |
| 画像・Prefab の置き場 | 取り込み先（既定 `Assets/UI`）の `<画面ID>/Images/`・`<画面ID>/Prefabs/`。ウインドウで変えられる |
| 画像の設定 | Sprite、ミップマップ無し、圧縮しない（デザインの確認用に色を変えない） |
| 文字 | TextMeshProUGUI。フォントは既定のもの。折り返さず、枠からはみ出して見せる。不透明度は文字の色に当てる |
| Canvas | Screen Space - Overlay。CanvasScaler は Scale With Screen Size、基準解像度は `canvas`、Match 0.5 |
| 並び | Horizontal / VerticalLayoutGroup。`spacing`（外形同士のすき間）と `padding_lrtb`。子の大きさは子に任せる。子は `items` の順に並べ、項目でない子は LayoutElement で外す |
| グループの不透明度 | CanvasGroup の alpha（画像には焼き込み済みなので、画像には当てない） |
| 絵が枠からはみ出した画像 | 部品の大きさは枠のまま、絵は子の `Image` に置く |
| Prefab | `_Prefab` の型ごとに 1 つ作る。基準は違いの無いインスタンス。ほかのインスタンスは Prefab から置き直し、位置・画像・文字などを差し替える。Prefab に無い部品は追加、インスタンスに無い部品は非表示。入れ子の Prefab に備えて深いものから作る |
| Button | 付けない（`Button?` は確認用の印） |
| EventSystem | シーンに無ければ作る（Input System があればその入力モジュール） |
| 取り込みの記録 | `<画面ID>/BuildUiToUnity_record.json`（画面・版・PSD・日時・シーン） |

## 段階 1: 取り込み（新規）

1. 画像を `Assets/UI/<画面ID>/`（場所は設定で変えられるようにする）にコピーし、Sprite として設定する
   - 同じ絵（`shared: true`）は 1 枚を使い回す
2. Canvas（`root`）を作る。CanvasScaler の基準解像度は `canvas` の値
3. `tree` をたどって GameObject を作る
   - 名前は `unity.name`（印を外した名前）。RectTransform に `unity` の値（anchorMin / anchorMax / pivot / anchoredPosition / sizeDelta）を入れる
   - `image` → Image（Sprite を割り当て）、`base_image` → 親自身の Image、`group` → 空の GameObject
   - `text` → TextMeshProUGUI（文字・大きさ・色・揃え。フォントは今は既定のもの。PSD のフォントとの対応は後で）
   - `layout` → Horizontal / VerticalLayoutGroup（間隔・余白は `layouts[]`。項目の大きさを子に任せるかは要確認）
4. `unity.prefab: explicit` の部品を Prefab にする（`Assets/UI/<画面ID>/Prefabs/` など。候補 `candidate` は作らない）。
   同じ Prefab のインスタンスは Prefab から置き直す
5. 取り込んだ結果をシーンに置く（今のシーンに追加 / 新しいシーンを作る）
6. **エラーのある版は、取り込む前に「エラー N 件があります。取り込みますか？」と確認を求める**
   （書き出しは止めない決まりなので、最終決定の取り込みで止める）
7. 取り込みの記録（どの版を取り込んだか）を残す（段階 2 の照合に使う）
8. layout.json の形の版（`format_version`）を確かめ、知らない版なら止めて知らせる（書き出す側が足したあと。全体の残作業）

確認: `samples/UIExport/Home` を取り込み、`preview.png` と見比べて同じ見た目になるか。

## 段階 2: 再取り込み（更新）（設計は 2026-10-18 にユーザーと決定）

デザイナーが PSD を直して書き出し直したとき、エンジニアが手を入れた Unity の画面を**作り直さずに更新する**。
前回取り込んだ記録・新しい書き出し・今の Unity の状態の 3 つを比べる（直下の `docs/03_versioning.md`）。

### 考え方: 追いかける必要があるのは、エンジニアの手が入った部品だけ

- エンジニアの手が入っていない部品（飾りなど）は、自由に消す・作り直す。細かいデザインの検討を妨げない
- エンジニアの手が入った部品（デザインの持ち分ではないコンポーネント・足した子・変えた値がある）は、照合に失敗しても**自動で消さない**
- 「Battle ボタン」のような大きな単位はエンジニアが処理を付けるので、自然に「大事な部品」として扱われる

### 照合の順番

| 順 | 方法 | 救えるケース |
| --- | --- | --- |
| 1 | ID（`unity.name` のパス）が同じ | ふつうの更新。グループを消して作り直しても、名前が同じなら同じ部品 |
| 2 | PSD で付け直した記録（layout.json の部品の「前の ID・前のレイヤー ID」。プラグインの付け直しで書く） | 作り直して名前も変えたが、PSD で付け直した |
| 3 | レイヤー ID（`layer_id`）が同じ | 名前の変更、別のグループへの移動。Unity でも名前を変える・移す（スクリプトも付いてくる） |
| 4 | 人が対応付ける | エンジニアの手が入った部品が見つからないとき、反映の前に一覧を出し、新しく増えた部品から選んでもらう（候補は同じ親・位置や大きさが近い・同じ種類の順）。「どれでもない」なら非表示で残す |

### 値の扱い（3 方向の比較。2026-10-18 にユーザーの指摘で決め直した）

部品の値ごとに、① 前に取り込んだときの値、② 今の Unity の値、③ 新しい PSD の値を比べる。
エンジニアの変更が正しいとは限らない（操作のミスもある）ので、**差がある所は自動で決めず、必ず人が選んでから確定する**。

| 場合 | 扱い |
| --- | --- |
| ① = ②（Unity で誰も触っていない） | デザインの変更として ③ を入れる（一覧には出す） |
| ② = ③ | 何もしない |
| ① ≠ ② かつ ② ≠ ③（エンジニアが変えていて、PSD とも違う） | **自動で決めない。** 部品の値ごとに「PSD の値にする」「Unity の値を残す」を選んでもらう |
| エンジニアが足したコンポーネント・子・イベント | 触らない |

- 反映ボタンでは、すぐには変えず、まず「これから行う変更の一覧」を出す。選ぶ所をすべて選んで「確定」したときだけ反映する
- 「Unity の値を残す」を選んだものは「PSD に戻す候補」として記録し、後で作る Unity → PSD の機能（直下の `docs/07_backlog.md`）で使う
- ① は取り込みのときに保存する layout.json の写し（`<取り込み先>/<画面ID>/BuildUiToUnity_layout.json`）から求める

対象の値: 位置・大きさ（RectTransform）、画像（Sprite）、文字（中身・大きさ・色・揃え）、並びの間隔と余白、不透明度。

### 確認の筋書き（dev_buildUiToUnity）

1. `Assets/UI/Home.unity` で、メニュー Dev > フッターにダミーのスクリプトを付ける（エンジニアの作業のつもり。`Assets/DevTest/`）
2. PSD でフッターを左端に寄せて書き出す
3. 反映して、Dev > ダミーのスクリプトを確かめる で、スクリプト・リスト・押したときの設定が残っているかを見る

### PSD から消えた部品

- エンジニアの手が入っていなければ削除する
- 入っていれば削除せず非表示にして、結果の一覧で知らせる（エンジニアが確かめてから消す）

### 安全網

- 取り込みの記録に、部品ごとの「ID・レイヤー ID・取り込んだ値・Unity の GameObject（GlobalObjectId）」を残し、次の照合に使う
- 反映は Unity の取り消し 1 回で戻せるようにする
- 反映のあとに一覧を出す: 更新・追加・残した値・非表示にした部品・対応付けた部品
- Prefab は Prefab の元を更新し、インスタンスの差し替えは段階 1 と同じ考え方で更新する

### PSD 側の対策（プラグイン。`exportPsdToUnity_plugin/docs/02_backlog.md`）

- 書き出しで、前の版にあった部品が ID でもレイヤー ID でも見つからなければ警告する
- パネルで新しいレイヤー（フォルダ）を選んで「付け直す」と、対応を PSD（XMP）に記録し、layout.json に前の ID・前のレイヤー ID を書く
- 運用の決まり: 「〇〇ボタン」のような大きな単位のフォルダは入れ替えず、その中で追加・削除する（PSD 作成の手引きに書く）
